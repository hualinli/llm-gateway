STEP 3 · 余额不足：在上游之前被拒（402）
────────────────────────────────────────────────────────────────────────
  $ # 企业 B 没有充值；rc-refuse-probe 路由到一个故意不可达的 Provider
  $ curl -s -o /dev/null -w '%{http_code}\n' -X POST http://127.0.0.1:18090/v1/chat/completions \
        -H "Authorization: Bearer <企业B的key>" -H 'Content-Type: application/json' \
        -d '{"model":"rc-refuse-probe","stream":true,"messages":[{"role":"user","content":"hello"}]}'

  → 企业 B -> 402 insufficient_balance
  → 对照（同一模型、企业 A 余额充足）-> 502 upstream_unavailable
  → 请求体里的 Provider 不可达：真打上游只会是 502；得到 402 说明 admission 在调用上游之前就拒绝了。
  → 响应不含余额数字：{"error":{"code":"insufficient_balance","message":"the organization's available balance cannot cover the maximum cost of this request","request_id":"3
