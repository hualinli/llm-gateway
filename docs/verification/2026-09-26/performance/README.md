# 本机 SSE 压测记录（2026-09-26）

## 结论

- 在这台 macOS/arm64 主机的 Docker Compose 环境里，固定到达率 100 和 300 请求/秒时，直连 Mock 与经过 Gateway 的请求各跑三轮，合计 9,000/9,000 条流完整结束，没有 HTTP 错误或缺失 `[DONE]`。300 请求/秒时 Gateway TTFT P95 三轮为 24.28–24.52 ms，直连为 24.23–24.42 ms。两条路径的差值小于这组实验可分辨的波动，**不能据此宣称零开销或负开销**。
- 闭环并发 1、16、64、128 及主 Provider 停止后的备用路径合计 9,240/9,240 条流完成。64、128 并发的吞吐和 P95 跨轮波动很大；这组数据不足以确定容量拐点或生产容量。
- 每组实验结束时事件级对账一致，pending=0、DLQ=0。第一组结束有 4,996 条 Stream 事件/台账记录，第二组结束有 9,497 条。两个数字包含开始前已有的本地 Demo 数据，不能作为本次请求数。

## 环境与口径

| 项目 | 值 |
| --- | --- |
| 主机 | macOS 27.0、arm64、10 核、32 GiB；Go 1.26.3；Docker Compose 5.1.2 |
| 代码 | 闭环实验 `ec24990b6ab72169b7185fd266831a5be62cf24b`；固定到达率实验 `4459c83`（两者之间只改变压测脚本） |
| 依赖 | Compose 中的 PostgreSQL 18.6、Redis 8.10.2 Alpine、项目 Dockerfile 构建的 Gateway/Control/Metering/Mock |

| 网关 | 单实例，活跃流上限 256；基准测试覆盖配置把每租户限流 rate/burst 调到 100,000，避免默认 20 次/秒策略影响代理性能对照；测试后恢复默认配置 |
| 负载 | 相同请求体、SSE 完整性检查；直连 `127.0.0.1:18080` 与经过 Gateway `127.0.0.1:8090`；每条流 10 秒超时；每组 3 次独立进程运行 |
| 指标 | TTFT 为第一个非空 SSE `data:` 事件；总耗时到 `[DONE]`；吞吐为成功请求数/整轮墙钟时间；P95 为单轮内请求分位数，再报告三轮中位值及范围 |
| 资源 | Gateway `/metrics` 每约 0.5 秒采样 CPU 秒数、RSS、堆、GC 次数；短轮次的峰值可能漏采，CPU 为采样区间平均核心数 |

闭环实验每轮请求数：并发 1/16/64/128 分别为 60/240/480/640；备用路径并发 16、240 次。固定到达率实验并发上限 64，目标 100/300 次每秒分别发出 600/900 次。固定到达率的实得吞吐略低于目标，是因为计时包含最后一批流完成的时间。

固定到达率下 Gateway 资源采样：100 请求/秒时每轮 RSS 采样峰值为 24.92–25.66 MiB、平均 CPU 约 0.14–0.16 核、GC 次数增加 27–34；300 请求/秒时 RSS 31.26–32.29 MiB、CPU 约 0.15–0.17 核、GC 增加 16–17。GC 次数受进程预热和采样窗口影响，不宜直接用两档差值推断内存效率。

Gateway RSS 的采样峰值在并发 1/16/64/128 档分别约为 22/27/39/51 MiB。并发 64、128 的轮次只有数秒，采样不能当作内存上界。高并发直连也出现明显波动，说明不能把全部变化归因于 Gateway；连接建立、Docker 桌面环境和压测端调度都有可能参与，尚未通过 profile 定位。

### 故障切换

停止 primary 后，用相同租户 Key 经 Gateway 请求 backup，并发 16、每轮 240 次：三轮共 720/720 条完整流成功。吞吐分别为 51.56、77.20、76.65 次/秒；TTFT P95 分别为 1,656.49、92.96、94.38 ms。第一轮明显退化，不能只报告后两轮；这次实验没有同时采集具体 retry/熔断时间线，因此尚不能断定原因。主备都停止时返回 502 的语义已在同一分支的一键 Demo 验收中单独验证。

## 复现与原始数据

在项目根目录、Docker 可用且所列端口未被占用时运行：

```bash
python3 scripts/benchmark-local.py --output data/benchmarks/local-closed-loop
python3 scripts/benchmark-local.py --arrival-only --output data/benchmarks/local-fixed-arrival
# 已有本地镜像且镜像仓库暂不可用时，可加 --no-build
```

脚本会启动专用 Compose 覆盖配置，创建本地 Demo Key，预热一次，执行各组三轮，保存每轮 JSON 与资源采样、等待最终对账，并在退出时停止 Mock、恢复日常 Gateway 限流。原始结果的可追溯副本：[闭环实验](closed-loop-raw.json)、[固定到达率实验](fixed-arrival-raw.json)。JSON 中时间长度以 Go `time.Duration` 的纳秒整数表示，`Status` 是 HTTP 状态码计数。

## 限制与下一步

- 这是单机 Docker Desktop、合成流的本地实验；不能外推真实 vLLM 推理负载、跨机网络或生产容量。
- 直连和 Gateway 路径使用不同主机端口/转发路径；当前观测分辨率不足以量化毫秒以下的透明代理开销。
- 尚未验证慢客户端、长流、固定连接爬升、Redis/PostgreSQL 断连恢复时的性能，也未定位并发 64/128 的波动源。下一轮应在独立稳定机器上采集压测端与 Mock 的资源、连接数和 Gateway profile，再逐级提高固定到达率。
