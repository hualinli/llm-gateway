# 平台、企业、成员业务方案

来源：2026-10-06 用户讨论并确认的业务范围。本文是目标产品规则，不表示功能已经实现。当前代码结构和与目标的差距见[当前系统架构](ARCHITECTURE.md)；实现状态和验证证据见项目状态及对应验收记录。

## 实施前提

项目仍处于开发阶段，允许重建开发数据库。无需迁移旧消费、旧 Key、旧成员关系或兼容旧数据。记录本方案不代表已经执行清库。

## 账户与身份

- 用户是全局登录身份，保存密码等个人信息。
- 账户分为个人和企业，共用余额、充值流水、调用计费与账单机制。
- 个人账户只有本人这一名管理员，服务端禁止邀请或加入其他成员。
- 企业通过成员关系关联用户，保存企业内角色、状态和月度额度。
- 一个用户可以保留个人账户，同时加入多个企业；各账户的资金、Key、额度与账单分别管理。
- 平台管理员身份独立于企业角色，不因为管理企业而自动成为企业成员。
- 第一版不支持个人账户直接转换为企业，需要团队能力时另建企业账户。

## 工作台与权限

| 身份 | 能力 | 权限边界 |
|---|---|---|
| 平台管理员 | 管理模型 endpoint、上游凭据、路由、价格、账户模型范围、企业开户与状态；手动入账；查看全平台计费、Token、上游成本 | 不直接管理企业成员 |
| 企业负责人（所有者） | 管理员全部能力；任免管理员、转让所有权 | 每个企业保留一名负责人，移除前必须转让所有权 |
| 企业管理员 | 管理自己的 Key；查看企业余额、账单和成员消费；邀请和审批普通成员、设置额度、暂停或移除普通成员 | 看不到其他成员的 Key 列表、名称或密钥；不能调整其他管理员或负责人 |
| 企业成员 | 管理自己的 Key；查看本人在当前企业的消费与额度；管理自己的密码等个人设置 | 无其他成员账单、企业全量账单、企业充值及成员管理权限 |
| 个人账户管理员 | 管理自己的 Key、余额、消费和个人设置 | 无团队成员功能 |

所有权限由服务端根据当前账户和成员关系判断。导航仅显示可用能力；切换页面账户不改变 Key 的付费归属。

## Key 与调用归属

- 成员自行创建、停用和删除自己的 Key，不设业务数量上限，可为每个 App 创建不同 Key。
- Key 固定绑定账户和该账户内的成员关系；调用方不能指定付费账户，Key 不支持迁移到其他账户。
- 不设置企业服务器 Key 类型；服务器 Key 归到实际负责人的成员关系下。
- 本人可以按 Key 查看自己的消费。企业管理员查看成员汇总及消费明细，明细可包含时间、模型、Token、费用，不暴露 Key 信息或请求内容。
- 企业管理员通过成员状态和额度控制消费，不直接管理成员 Key。暂停或移除成员后，其全部企业 Key 均不能发起新调用。
- 人员交接由接任者创建自己的 Key、替换服务配置，再停用旧 Key。
- 企业余额不足时不能自动扣个人余额。

## 余额、额度与结算

- 个人与企业充值余额长期保留，不按月清零。
- 企业成员共享企业余额，消费独立归属到成员；不建立成员充值钱包。
- 成员额度是月度消费上限，按北京时间自然月计算，未用额度不结转。
- 企业负责人和管理员默认无个人上限，消费仍归属本人并计入企业账单。
- 新普通成员必须明确设置额度；0 表示禁止消费，“不限额”单独表示。
- 月中调整上限立即影响新调用，不重置已用额度；降低上限不取消已受理请求。
- 准入同时检查企业可用余额和成员当月已用、预占金额；两者一起预占、结算和释放，支持并发并防止重复扣费。
- 按实际销售费用结算，多余预占释放；失败且确认没有产生费用时释放预占。费用未知时保留待核对状态。
- 已受理调用在成员或企业停用后继续结算。跨月调用的额度预占与结算归入同一准入月份，消费记录保留实际时间用于账单解释。
- 消费保存账户、成员、Key、模型、Token、采用的价格和实际销售费用；企业及成员汇总取自同一计费事实。
- 第一版不增加企业整体月度预算，不支持成员额度跨月累计。

## 模型范围与价格

- 平台给账户开放模型，第一版账户内全部成员共用该范围；企业管理员不配置成员级模型权限。
- 平台为不同模型设置不同销售价格，个人和企业共用一套价格，支持输入、输出 Token 分别定价。
- 每次调用保存采用的价格，调价不改变历史账单。
- 上游成本和销售费用分别记录，成本仅平台可见；缺少证据时标记未知，不以售价冒充成本。

后续版本允许企业管理员在平台给企业开放的模型范围内，进一步限制每个成员可用的模型。第一版不实现此功能。成员权限只能缩小企业范围，不能获得平台未开放的模型；后续需同时实现配置页面、服务端授权和网关调用准入，不能仅隐藏前端选项。

## 开户、加入与角色变更

- 个人可自助注册并使用个人账户，加入企业后保留个人账户。
- 企业由平台管理员手动创建，或通过企业开户激活码创建。
- 用户通过企业编号申请加入，填写名称不直接建立成员关系；由企业负责人或管理员审批。
- 成员邀请绑定邮箱，接受后直接加入；邀请时明确普通成员额度。
- 企业开户激活码和成员邀请分开，权限与用途不能混用。
- 负责人可以任免管理员和转让所有权；管理员仅管理普通成员。
- 管理员降为普通成员时必须设置额度，当月已发生消费继续累计。
- 成员退出或被移除后企业 Key 停用，历史记录保留；再次加入使用新的成员关系和 Key。
- 企业停用阻止整个企业的新调用，不影响用户个人账户。

## 充值与审计

- 第一版由平台管理员确认付款后手动入账，不接在线支付。
- 企业充值由负责人或管理员对接平台，普通成员无企业充值入口；个人充值由本人对接平台。
- 入账记录金额、原因、操作人、时间和外部付款凭据，并防止重复入账。
- 错误入账通过冲正流水修正，保留原记录，不直接修改余额或删除流水。
- 成员状态、角色、额度、企业状态、模型范围、价格和资金操作保留审计记录。

## 实施顺序

1. 统一用户、账户、成员关系和 Key 归属，重建开发数据库，落实负责人及角色边界。
2. 完成开户、注册、邀请、加入审批与个人设置，按角色调整工作台及入口。
3. 接入账户余额和成员月度额度的统一准入、预占、结算及失败恢复。
4. 完成平台模型管理、账户模型范围、价格和手动入账，保护上游秘密并记录审计。
5. 完成各角色的真实消费统计，验证数据隔离和调用资金边界。

现有组织钱包、Key 归属、用量隔离和持久结算可作为实现基础，但需按新方案调整。现有页面与演示费用展示不代表本方案已经完成。
