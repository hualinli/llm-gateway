# 当前实现状态

本文记录当前代码行为与验证边界；目标规则见[业务方案](BUSINESS.md)，组件和数据流见[架构说明](ARCHITECTURE.md)。

Console 支持公开注册个人账户、平台开户企业、激活码兑换、加入申请与审批、邮箱邀请和多账户切换。平台管理员身份独立于企业角色。企业成员角色为 `owner`、`admin`、`member`；企业只有一名 owner，普通 admin 只能管理普通成员。个人账户没有团队操作。成员暂停会阻止新调用，但本人仍可查看历史消费和额度。

企业成员各自创建和停用自己的 Key。Key 绑定创建时的账户和成员关系，企业管理员看不到其他成员 Key。成员月度额度为 `null` 不限额、`0` 禁止新消费、正数为微元上限。第一版不设企业整体月预算，个人和企业钱包余额不会按月重置。移除后再次加入会创建新的成员关系，旧 Key 不再有效，历史消费仍保留。

正式消费按请求准入时的北京时间月份归属，迟到结算不会改变消费月份。已结算的真实扣款计入消费；待结算和待核对项目单独展示，不当成已消费。资金流水按实际入账时间记月。企业与个人使用充值账户，平台手动入账并通过冲正流水纠正；没有在线支付。上游成本只向平台展示，未知成本不会按零处理。

平台工作台支持 Provider、凭据、路由和价格管理；账户模型范围与调用准入的完整全栈验收仍待完成，不能仅凭页面或 OpenAPI 定义视为已验证。第一版企业成员共用账户可用模型范围；成员级模型限制仍是后续 TODO。

本地类型检查、构建、单元测试和部分 Console HTTP/数据库检查已运行；完整发布候选与浏览器全栈验收尚待集成后完成。生产 mTLS 部署、真实付费 Provider、长时间稳定性和生产备份恢复仍未验证。Control 配置写入按单个 writer 设计。

开发数据库允许重建，不要求迁移旧开发消费、Key 或成员关系；这不代表生产账务数据的删除流程。启动和测试入口见[开发说明](DEVELOPMENT.md)，接口契约见[OpenAPI 文件](openapi/console-v1.yaml)，账务异常处理见[账务恢复手册](runbooks/billing-recovery.md)。
