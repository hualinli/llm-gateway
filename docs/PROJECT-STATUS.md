2026-10-11 新增原生 `POST /v1/responses`，支持与 Responses 上游匹配的流式纯文本请求，复用鉴权、模型授权、限流、额度预占和持久计费。平台可选择 `openai-responses` 接入点；两种协议的路由分别选择匹配上游。第一版不包含协议转换、非流式、工具、多模态或上游状态引用；网页模型试用仍使用 Chat。配置与限制见[原生 Responses](NATIVE-RESPONSES.md)。隔离 PostgreSQL 与 HTTP 模拟上游下的 Responses 计费测试在竞争检查中通过，覆盖正常/截断/失败结算、幂等扣款、用量异常和终态前收据写入。全库 Go 测试、改动包竞争检查及 vet、前端 75 项测试、类型检查和构建通过；没有运行真实付费上游或完整浏览器验收。

Console 支持公开注册个人账户、平台开户企业、激活码兑换、加入申请与审批、邮箱邀请和多账户切换。平台管理员身份独立于企业角色。企业成员角色为 `owner`、`admin`、`member`；企业只有一名 owner，普通 admin 只能管理普通成员。个人账户没有团队操作。成员暂停会阻止新调用，但本人仍可查看历史消费和额度。

企业成员各自创建和停用自己的 Key。Key 绑定创建时的账户和成员关系，企业管理员看不到其他成员 Key。成员月度额度为 `null` 不限额、`0` 禁止新消费、正数为微元上限。第一版不设企业整体月预算，个人和企业钱包余额不会按月重置。移除后再次加入会创建新的成员关系，旧 Key 不再有效，历史消费仍保留。

正式消费按请求准入时的北京时间月份归属，迟到结算不会改变消费月份。已结算的真实扣款计入消费；待结算和待核对项目单独展示，不当成已消费。资金流水按实际入账时间记月。企业与个人使用充值账户，平台手动入账并通过冲正流水纠正；没有在线支付。上游成本只向平台展示，未知成本不会按零处理。

平台工作台支持 Provider、凭据、路由、价格、平台模型目录和账户模型范围管理。调用与 `/v1/models` 按平台、账户及本人 Key 的范围交集执行；账户可继承平台目录、明确禁用全部模型或指定模型子集。第一版企业成员共用账户可用模型范围；成员级模型限制仍是后续 TODO，规则记录在[业务方案](BUSINESS.md)。
