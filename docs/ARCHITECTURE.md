# 当前系统架构

本文说明当前实现的数据边界和主要流程。平台、企业和成员的业务目标见[业务方案](BUSINESS.md)，验证进度与尚未验证的运行条件见[当前实现状态](PROJECT-STATUS.md)。接口字段以[OpenAPI 契约](openapi/console-v1.yaml)为准。

## 组件与数据边界

| 组件 | 主要职责 | 数据边界 |
|---|---|---|
| Web | 登录、账户切换、角色工作台和请求操作 | 页面控制不代替服务端授权 |
| Console | 注册、会话、企业与成员、模型和 Provider 管理、账务查询 | IAM、成员、额度、账务及审计写入 PostgreSQL；配置经 Control 发布 |
| Control | Key、上游凭据和版本化模型路由配置 | 权威配置 writer；凭据秘密不随普通配置快照发布 |
| Gateway | Key 认证、账户与成员检查、资金准入、限流、模型代理 | 使用已应用的 Control 配置，并读取 PostgreSQL 中的账户与计费事实 |
| Metering | 收据派发、消费结算、恢复、对账 | PostgreSQL 是资金事实源；Redis 仅承载限流与事件传输 |
| PostgreSQL | 用户、组织、成员、模型价格、额度、执行、收据、资金流水和审计 | 服务间共享存储，但业务表的写入责任明确 |

## 身份、账户和 Key

用户是全局登录身份，可以拥有个人账户并加入多个企业。个人账户不允许团队成员；企业成员关系独立记录角色、状态、月上限和创建时间。平台管理员权限与企业角色分开判断，不因平台管理权限自动成为企业成员。

Key 固定属于创建时选择的账户及当前成员关系。Gateway 根据 Key 确定实际计费账户，不接受调用方传入账户来改变扣费归属。成员关系被暂停或移除后，关联 Key 不再发起新调用；同一用户重新加入企业会得到新的成员关系，旧 Key 不随重新加入而恢复。执行保留发生时的 `membership_id`，而组织内用户的当月额度计数不会因移除后重加而清零。

企业 owner 可管理组织成员及角色；admin 只能管理普通 member，不能调整其他 admin 或 owner。成员和管理员只能创建、查看、停用自己的 Key。企业管理页面可展示成员用量，但成员 Key 标识、名称、前缀和秘密不会出现在他人视图或审计详情中。平台管理员的控制面权限不会扩展成企业成员权限。

## 模型请求与额度结算

```text
调用方
  → Gateway 验证 Key 并确定账户与成员关系
  → 校验账户和成员状态、余额、月额度及模型授权
  → 一个 PostgreSQL 事务检查余额和成员月额度并预占
  → 限流、读取已发布路由并代理到 Provider
  → 在发送成功流终止标记前持久化用量收据
  → Metering 派发收据，结算实际费用并释放多余预占
```

余额和成员额度在准入事务中共同检查、预占。成员额度为 `null` 表示不限额，`0` 阻止新消费；下调上限不会撤销已准入请求。额度和消费报表按执行准入时的 `quota_month` 归属到 Asia/Shanghai 自然月，迟到结算继续归入该月。账本资金流水另按真实 `posted_at` 时间展示月份。

结算后的实际扣款才进入消费总额。尚未结算、需要人工核对或没有可确认费用的执行单独显示；未知 Token 或 Provider 成本保留未知状态。组织和成员账单没有 Provider 成本字段，平台成本汇总只累加有已知价格的部分并单列未知数量。

成功用量收据必须在 Gateway 写出 `[DONE]` 前持久化。Metering 消费采用至少一次方式；稳定执行 ID 和唯一约束防止重复扣费。未结算的 PostgreSQL 收据可以在 Redis 故障后重新派发。恢复任务需要符合执行状态、实例心跳、收据和恢复窗口条件，不能只因时间经过就释放预占。细节见[账务恢复手册](runbooks/billing-recovery.md)。

## 配置发布与模型范围

Console 通过 Control 管理 Provider、凭据和路由。路由按版本整体替换并通过 expected version 避免覆盖并发修改。Control 生成配置快照，Gateway 使用已应用的版本；上游秘密通过受保护的凭据流程读取，不写入普通配置快照。

平台模型目录和账户模型范围属于 Console 的配置与准入边界；账户模型范围的完整全栈行为仍待验收。同一账户成员第一版共用可用范围。价格版本在执行准入时固定，因此后续改价不改变历史账单。Key 级 allowlist 仍是单独的更窄限制。成员级模型范围尚未实现，属于业务 TODO，见[业务方案](BUSINESS.md)。

## 当前验证边界

本地开发库允许重建，旧开发数据不要求迁移。账户、成员、额度和计费行为以服务端检查为准；浏览器隐藏入口不能构成授权。完整发布候选和浏览器全栈验证尚未完成。生产 mTLS、真实付费 Provider、长时间稳定性和备份恢复仍需单独验证；Control 配置写入按单个 writer 运行。
